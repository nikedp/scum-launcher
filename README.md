# SCUM Lab Launcher

Windows-лаунчер для синхронизации собственной сборки модов SCUMLab через GitHub Releases.

**Версия 0.1.6 экспериментальная.** Тёмный игровой интерфейс: графитовые панели, мятный акцент и стандартное расположение кнопок управления окном справа. Кнопки полностью отрисовываются приложением, без смешивания с нативной Windows-темой. Проверены транзакции лаунчера и серверное монтирование PAK с параметром `-fileopenlog`. Стул и рецепт ещё требуют проверки в мире. Для установки нужно явно разрешить экспериментальный релиз.

## Очистка клиента и кэша

Закройте клиент SCUM и нажмите «Очистить» в блоке обслуживания. После подтверждения вся папка `%LOCALAPPDATA%\SCUM` перемещается в `%LOCALAPPDATA%\SCUMLabLauncher\client-backups\<дата-id>`; при следующем запуске игра создаст новую. Это сбрасывает настройки, кэш и прочие локальные данные, включая одиночные сохранения; они остаются в копии. Кнопка «Копии» открывает папку резервных копий. Для восстановления закройте игру и перенесите нужную копию обратно как `%LOCALAPPDATA%\SCUM`, предварительно сохранив новую папку, если она уже появилась. Автоматическое закрытие игры и удаление копий не выполняются. Установленная игра и серверный Saved не меняются. Эта операция может помочь при сбое локальных данных, но не исправляет все причины крашей.

## Использование

1. Скачать `SCUMLabLauncher.zip` из [Releases](https://github.com/nikedp/scum-launcher/releases/latest), распаковать и запустить `SCUMLabLauncher.exe`.
2. При запуске лаунчер ищет клиент в библиотеках Steam на всех дисках. Кнопка «Найти игру» дополнительно проверяет локальные диски (до 15 секунд, глубина до 5 папок). Если найдено несколько клиентов, выберите нужный; путь сохраняется. Для более глубоко вложенных или недоступных папок используйте «Выбрать…».
3. Закрыть игру перед синхронизацией. Для сервера отдельно остановить серверный процесс.
4. Нажать «Проверить обновления», затем «Синхронизировать».
5. Запустить Steam и войти в свой аккаунт. После успешной проверки нажать «Запустить SCUM»: лаунчер запускает установленный клиентский EXE с `-fileopenlog`. Адрес тестового сервера указывается в Direct Connect. Клиентский запуск и подключение с этой сборкой ещё требуют проверки на ПК игрока.

PAK устанавливаются в `SCUM/Content/Paks/SCUMLab`. Сервер нужно запускать с `-fileopenlog`: этот вариант проверен на SCUM 1.3.6.1.177547. Файлы служб античита и конфигурация Windows не меняются. Если сборка уже устанавливалась лаунчером 0.1.4 или старше в корень Paks, сначала нажмите «Откатить файлы», затем повторите синхронизацию. Старые журналы отката поддерживаются.

Лаунчер проверяет Steam Build ID и SHA256 загруженных файлов, извлекает реестр из собственной локальной установки и добавляет метаданные нашей сборки. Полный игровой реестр, ключи, сохранения, настройки и учётные данные на GitHub не отправляются. Дополнительные программы, Node.js и Unreal Editor на ПК игрока не нужны; используется .NET Framework Windows.

При пустом поле пути кнопка проверки открывает выбор папки. Путь можно вставить в кавычках, в том числе с пробелами. Некорректный или относительный путь получает понятную подсказку.

## Обновление лаунчера

Кнопка «Обновить лаунчер» в заголовке проверяет последний релиз GitHub и при наличии новой версии скачивает ZIP, сверяет SHA256 с digest GitHub и проверяет версию EXE. Затем окно закрывается; встроенный помощник дожидается выхода процесса, сохраняет предыдущий EXE и атомарно заменяет файл. Новая версия запускается автоматически. Папка игры для этого не нужна; настройки пути сохраняются.

Если замена или запуск не удались, предыдущий EXE сохраняется либо восстанавливается. Резервная копия имеет имя EXE с суффиксом `.previous-<id>.bak` рядом с лаунчером; подробности находятся в `%LOCALAPPDATA%\SCUMLabLauncher\updates`. Для установки в защищённую папку нужны права записи. Лаунчер не повышает права сам.

Для перехода с 0.1.0/0.1.1 нужно один раз скачать актуальный ZIP и заменить EXE вручную. После этого следующие версии устанавливаются кнопкой внутри приложения.

Сейчас поддержаны клиент Steam Build `26621909` и сервер `26621903` (SCUM 1.3.6.1.177547). После обновлений SCUM требуется совместимый релиз сборки. Лаунчер не обновляет саму игру и не управляет античитом.

## Откат

Кнопка «Откатить файлы» восстанавливает предыдущее состояние управляемых PAK. Перед заменой создаётся резервная копия; незавершённая транзакция восстанавливается при следующем обновлении. Если файлы были вручную изменены, операция останавливается. Чужие моды и штатные PAK не удаляются. При наличии нескольких реестров модов автоматическая сборка останавливается, чтобы не затереть их регистрацию.

Состояние, staging и резервные копии хранятся в `SCUMLabLauncherData` рядом с папкой SCUM. Эта папка локальная. Откат файлов не отменяет изменения игрового мира; перед тестом экспериментальной мебели владелец сервера сохраняет мир отдельно.

## Разработка

```powershell
./build.ps1 -Test
./test-self-update.ps1
```

Сборка использует штатный Microsoft C# compiler из .NET Framework, создаёт `dist/SCUMLabLauncher.exe`. Самопроверки используют только новую тестовую папку. Они проверяют целостность загрузок, пути, совместимость, установку, отказ посреди транзакции, откат, ручные изменения и сохранность чужих файлов. Бинарный формат локального PAK также проверен официальным UnrealPak на реестре локальной серверной сборки; игровые файлы в репозиторий не входят.

Публичные релизы содержат только собственный PAK, дельту метаданных, манифест и лаунчер. Код написан в этом проекте; сторонние PAK в сборку не включены.

## Выпуск релиза

Манифест `release/channel.json` задаёт tag, версию, поддержанные Steam Build ID и SHA256 каждого payload. GitHub Actions собирает и проверяет EXE, затем публикует новый тег из манифеста. Уже существующий релиз не перезаписывается: для изменения опубликованных файлов требуется новый тег и версия. Загрузка релизов публичная и не требует токена на ПК игрока.

Манифест и payload перед публикацией проверяются `prepare-release.ps1`. На GitHub идут только файлы этой папки проекта; локальные исследовательские каталоги сервера не публикуются.
